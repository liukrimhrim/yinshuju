# MVP 切分与首发规格

Type: grilling
Status: resolved
Blocked by: 09, 10

## Question

规划收官票：定首发（v1）范围与里程碑，产出 MVP 规格文档。必含决策：编辑器/阅读 UX 骨架（输入区+实时预览布局、手机端形态、翻页交互粗案）；导出规格集（壁纸尺寸档位、对开大图、PDF 开本与多页）；字体自定义 UI 范围（内置几款、是否允许用户上传、默认字体）；句读点选 UI 归属（v1 靠输入标点是否已够）；印章编辑深度（内容/形状/朱文白文；开工前复核说文篆体授权两说）；简繁/旧字形开关；PWA 化时机；是否需要任何后端（默认无，若分享功能倒逼再议）；里程碑切分。此票关闭即地图收官——动工前再无待决问题。

补充（用户需求，2026-07-31）：**导出必须支持多比例、多格式，适配社交平台发布**。本票需定：

- 比例档位集：如 手机壁纸 9:19.5、小红书 3:4、Instagram 1:1 / 4:5、横屏对开 等——具体平台清单与各平台当前推荐尺寸**开工时现查**（分辨率/尺寸易过期，不得凭记忆写死）。
- 关键设计分叉：各比例是「版式自适应重排」（引擎全参数化，方形可用对开双半叶、竖长可增行数）还是「固定半叶+加边/裁切」？倾向前者（这是布局引擎路线的差异化红利），在此票定案。
- 格式：PNG 之外至少 JPEG（做旧主题的噪声纹理 PNG 近 10MB，JPEG 可大幅压缩）；质量参数与各平台体积上限对齐。

补充（用户需求，2026-07-31）：**印章必须支持朱文/白文可选，字体必须用篆书**（非楷体兜底为默认）。由此收紧：

- 说文篆体（全字库《说文解字》字型，6721 字）的授权两说复核升级为**印章功能的硬前置**——若"个人与系统发展使用"标注属实，需评估替代（崇羲篆体 CC-BY-ND 禁改作，整字体 webfont 嵌入或 text→path 出图是否合规需专门论证）。
- 说文小篆仅 6721 字，用户姓名/斋号缺字概率不低——缺字时的 UX 要在本票定：提示缺字并建议改字？允许该印退楷（调研的历史依据：宋楷书官印、明清隶楷藏书印）？还是混排（调研结论：不混排）？
- 朱文=红字白底框、白文=红底挖白字，SVG 技法均已在印章调研票定案，非本票范围。

补充（用户需求，2026-07-31）：**行格必须用户可自定义——列数（半叶行数）与每列字数均可调**。引擎侧已天然支持（原型的 contentCols/rows 就是参数）。本票需定 UI 形态：预设制式（版式规范票的常用域：半叶 8–15 行 × 行 16–22 字，及黄善夫本 10×18、殿本 8×17 等名本预设）+ 自由数值输入的边界（超出域是否放行/警告）；与"多比例自适应重排"共用同一个版式参数面板——两条需求合流：参数面板是一等公民 UI。

补充（vRain 研读，2026-07-31）：① 字体 fallback 混排必须做**跨字体度量微调**（参考字实测高度差自动缩放）与**描边配平加粗**，否则补字忽大忽小——列为兜底链的质量要求；② PDF 出口加**目录书签**（从 # 篇题自动生成 outline）；③ vRain 的右侧旁线标记集（书名线/圈注/点注/线注）与手动排版控制符（分页符/顶格/字号缩放）列为 **markup v2 候选清单**，本票只决定 v1/v2 切线，不设计语法。

## Answer

用户拍板四分叉：**M1 = 三出口全量**（壁纸/阅读/PDF 一次到位）；**多比例导出 = 版式自适应重排**（每档比例重算网格，方形出对开）；**印章缺字 = 明确提示 + 一键整印退楷**（不混排）；**字体 = 内置三款 + 支持用户上传**（TTF/OTF，导出走 opentype.js 运行时子集，授权自负）。

其余按既往决策合拢：无后端、PWA 与句读点选 UI 与旧字形层与 markup v2 旁线集均出圈到 v2；建造顺序 A 核心闭环 → B 导出（含 Safari 实测）→ C 印章（硬前置=说文篆体授权复核）→ D 收尾发布，A/B 不被 C 阻塞。
