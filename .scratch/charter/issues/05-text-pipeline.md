# 简繁转换与自动句读

Type: research
Status: resolved

## Question

文本管线两件事的现成方案：a) 简→繁：OpenCC（opencc-js）的变体怎么选（s2t / s2tw / s2twp），旧字形/异体字（为→爲、册→冊一类）能否再进一步，纯前端的体积代价；b) 古文自动句读：现成模型/API/JS 方案盘点（质量、能否纯前端跑、授权），若无靠谱纯前端方案，降级路径是什么（手动标记/半自动点选）。给出推荐与降级链。

## Answer

详见 [研究文档](../research/05-text-pipeline.md)。

**简→繁**：opencc-js（nk2028 维护，MIT+Apache-2.0，2026-07 仍发版，唯一活跃 JS port）；全量 gzip 557KB，ESM 可按需引词典。变体用 **s2t**——直觉验证成立：s2twp 的惯用语替换（内存→記憶體）对古文有害，s2tw 也会把 裏/着 改成现代台标 裡/著，都不要。一简对多繁（後稷类错）无权威错误率数据，治理 = 内置 ~30 高危字转换后高亮人工改选 + CustomConverter 个人词典。

**旧字形**：同码位的字形差异用传承字形字体免费解决（I.Ming 一點明體/尚古系列在维护）；异码位（爲眞衆册裏卽）无现成包，从 ichitenfont《傳承字形推薦形體表》手工整理 ~50 字映射，做可选开关。

**句读**：**无免费稳定托管 API**（吾与点域名已死、籍合网收费、识典古籍无开发者 API）。开源模型 guwen-punc（Apache-2.0，简体输入）可用但纯前端要 60-110MB opt-in 下载。**管线顺序：先简体句读 → 再 s2t → 最后旧字形层**（句读模型多为简体语料训练）。

**降级链定案建议**：① 默认手动圈点 UI（复用句读符渲染）→ ② 用户自带 LLM API key 前端直连 → ③ 本地模型 opt-in（远期）→ ④ 外链识典古籍手工往返（只写帮助文档）。首发只做 ① + 简繁全套；② 第二步。
